## 1. Executive Summary & Objective

Modern cloud computing infrastructures (such as OpenStack) generate massive volumes of unstructured, heterogeneous event logs across distributed compute, storage, and networking layers. Manual log inspection is infeasible, while traditional keyword matching fails to detect latent, multi-step execution failures.

This project implements an end-to-end unsupervised telemetry analysis pipeline:
1. **Raw Log Ingestion & Parsing:** Extracts structured event templates from raw OpenStack Nova compute logs using **IPLoM** (*Iterative Partition-based Log Mining*).
2. **Session Windowing & Featurization:** Groups log lines chronologically by virtual machine identity (`instance: <UUID>`) and maps them to TF-IDF event frequency matrices.
3. **Matrix Decomposition & Anomaly Detection:** Applies **Robust Principal Component Analysis (RPCA)** via Principal Component Pursuit to decompose the session-event matrix into:
   $$\mathbf{D} = \mathbf{L} + \mathbf{S}$$
   where $\mathbf{L}$ models normal baseline cloud execution paths (low-rank), and $\mathbf{S}$ isolates sparse deviations and failure anomalies.

## 5. Root Cause Analysis & Diagnostic Findings

### Finding 1: Out-of-Sample Subspace Projection Flaw (Critical Code Defect)
In [`loglizer/models/RPCA.py`](loglizer/models/RPCA.py#L149-L156), the `predict(X)` method contains an indexing bug:
```python
# Current implementation in RPCA.py:
for i in range(X.shape[0]):
    TF = self.S[i] > self.threshold  # Uses training matrix S instead of projecting X_test!
    if TF.any():
        y_pred[i] = 1
```
Because `self.S` is the sparse decomposition of the **training** matrix, calling `predict(X_test)` evaluates row indices against the training residual rather than projecting $X_{\text{test}}$ into the orthogonal complement of the learned low-rank subspace ($\mathbf{P}_{\mathbf{L}}^{\perp}$). This directly explains the drop in test F1-score from $0.780$ to $0.152$.

### Finding 2: Information Loss from Unordered Bag-of-Events
The TF-IDF `FeatureExtractor` treats event logs as an unordered set. In cloud computing:
- VM provisioning is a state-dependent sequence (`SCHEDULING` $\rightarrow$ `NETWORKING` $\rightarrow$ `BLOCK_DEVICE_MAPPING` $\rightarrow$ `ACTIVE`).
- Anomalies often maintain identical event counts to normal sessions while violating valid state transition orders.

### Finding 3: Static Global Thresholding
The current threshold ($\tau = 0.8$) is hardcoded without empirical tuning on validation ROC/PR curves or Extreme Value Theory (EVT), leading to high false negatives on subtle anomalies (such as DHCP timeouts).

## 6. Recommended Next Steps for Iteration 2

1. **Subspace Projection Fix:**
   Implement true out-of-sample projection:
   $$\mathbf{S}_{\text{test}} = \mathbf{X}_{\text{test}} - \mathbf{X}_{\text{test}} \mathbf{V}_r \mathbf{V}_r^T$$
   and flag anomalies where $\|\mathbf{S}_{\text{test}}[i]\|_2 > \tau$.
2. **Dynamic Threshold Optimization:**
   Sweep thresholds over the training/validation split to maximize F1-score.
3. **Sequential & Temporal Features:**
   Incorporate transition probabilities (Bigrams / Markov transitions) between Event IDs to capture out-of-order failures.
4. **Cloud Pipeline Readiness:**
   Transition the parser from batch IPLoM to streaming online log parsers (e.g., Drain3) for real-time telemetry processing.
